1. Purpose

MSME shops (textiles, bottled FMCG, stamped metal, SMT, ceramics, carton print) need 100% visual gates without a dedicated AOI cell. LineSight splits work three ways:

  • HuskyLens 2 sees the unit — onboard YOLO, classification, instance segmentation, OCR, barcode, and self-learning.
  • RDK X5 8GB owns policy — pixel-to-mm, spec limits, AQL sampling, GPIO / CAN reject.
  • LineSight is the operator surface — lot genealogy, override, teach set, on-demand diagnosis.

This document is the synthesis of that pipeline: devices, stages, protocols, MSME recipes, and the software that the live console implements. The in-browser LineSight run is a faithful demo of the chain (simulated HuskyLens feed). Plant deployment uses the same stages over USB 3.0 / UART against real hardware.

3. Six-stage pipeline

01 Capture→ 02 Edge vision→ 03 Transport→ 04 Fusion & policy→ 05 Verdict→ 06 Reasoning
01
Capture

GC2093 2 MP at 60 fps. Fill LEDs on the HuskyLens 2; optional microscope lens for SMT pads and print register. Exposure held constant per recipe so shade ΔE and fill-level pixels stay comparable across a lot.

GC2093 2 MP
02
Edge vision

K230 runs the recipe’s model mix locally: object recognition, classification, instance segmentation, color, OCR, barcode/QR, object tracking, and the self-learning classifier. Output is blocks (xywh, label, confidence) plus optional MCP semantic frames — not a raw video dump.

HuskyLens 2 · 6 TOPS
03
Transport

USB 3.0 for stills / MJPEG when needed; Gravity UART (115200, HuskyLens V2 protocol 0x55 0xAA) for blocks and arrows. Typical inspect-path latency 5–8 ms on the demo line. Zero drops is the gate for a production link.

USB 3.0 / UART 115200
04
Fusion & policy

RDK X5 applies homography (pixel → mm), spec min/max, hole-count / fill-ml calibration, AQL skip-lot, and SPC. BPU can fuse a second MIPI view. Reject pulse on GPIO or CAN FD to the solenoid / press. This is where MSME mix lives: one image, many SKUs.

RDK X5 BPU · 10 TOPS
05
Verdict

LineSight stamps pass fail hold. Operator may override. Unit joins lot genealogy with cycle time, score, detections and measurements. Hold is for borderline confidence, not a silent pass.

LineSight console
06
Reasoning

On operator request only: Grok reads the fail packet (recipe, detections, specs) and returns Cause / Process / Operator / CAPA. If the xAI key is quota-blocked, an on-device policy note runs the same four-line shape from the recipe rules. Never called per frame.

Grok MCP · on-demand

4. Protocol and data

HuskyLens 2 binary frame (V2 protocol):

0x55 0xAA | CMD | ALGO_ID | LEN | DATA | CHK

Algorithm IDs used on this line: object recognition (2), tracking (3), color (4), classification (5), self-learning (6), instance seg (7), OCR (11), barcode / QR / tag. LineSight consumes the decoded blocks as:

{ id, label, x, y, w, h, confidence, kind, severity? }

Measurements are policy, not camera: each recipe declares specMin / specMax / target. A unit fails if a critical defect block fires or any measurement is out of spec. Score starts at 100 and is penalised per defect and OOS channel.

6. LineSight software map

Surfaces

  • Station — live HuskyLens viewport, pipeline rail, verdict, diagnose
  • Pipeline — hardware topology and this synthesis
  • Lots — yield, score trend, defect Pareto, genealogy
  • Recipes — six MSME SKUs, load onto the station
  • Teach — gold / defect samples → K230 self-learn deploy

Runtime rules

  • No accounts. Session state in memory (demo lot seeded).
  • Grok is user-initiated, 500-token cap, never per frame.
  • On 403 / missing key: on-device Cause / Process / Operator / CAPA.
  • Self-learn deploy gated at 4 gold + 4 defect (8+8 preferred).
  • Demo line is labelled as such — not a fake plant handshake.

7. Plant wiring (when hardware is on the bench)

  1. Power HuskyLens 2 from 5 V. Load the recipe model set (or custom YOLO from Model Hub).
  2. USB 3.0 Host on RDK X5 ← HuskyLens 2 Type-C. UART 115200 on Gravity as fallback / block stream.
  3. RDK X5 Ubuntu 22.04 service: decode protocol, apply recipe JSON, pulse GPIO/CAN on fail.
  4. LineSight on the same board (or a shop PC) over HTTP to that service.
  5. Reject solenoid / tower light on GPIO; press interlock on CAN FD for metal.
  6. Teach gold/defect from the first-article lot; deploy to the K230 self-learning head.

Estimated station BOM (indicative, 2026): HuskyLens 2 ~USD 90, RDK X5 8GB board, 24 V reject solenoid, enclosure, fill lighting. Well below a packaged AOI cell, which is the MSME constraint.

8. Why the split holds for MSME

On-device first

Classification and OCR stay on the K230. Bandwidth and privacy stay on the line. Cloud is not in the cycle-time path.

Board does policy

Recipes, AQL and the reject pulse live on the X5. Swap SKU without retraining the whole stack. High mix, short runs.

LLM on demand

Grok reads a fail packet only when an operator asks. Quota stays bounded. CAPA language matches a setter, not a data scientist.

9. Open items for a live cell

  • Calibrate homography per nest (checkerboard still on first article).
  • Map GPIO bit to the actual reject valve / tower; debounce 3-fail-in-10 as a line stop.
  • Balance teach sets (minimum 8 gold + 8 defect per class) before raising confidence thresholds.
  • Persist lots to the plant MES or a local Postgres when accounts exist; this demo does not.
  • Wire HuskyLens MCP to Grok only on the shop VLAN, never the public internet per frame.
